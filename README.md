# 공공 API 상태판 (kr-public-api-status)

한국 공공데이터 API 20곳이 **응답하는지, 어디서 닿는지** 주기적으로 재서 공개합니다.

👉 **https://Raonkim.github.io/kr-public-api-status/**

## 왜 만들었나

- **공식 상태판이 없습니다.** 공공데이터포털에는 기관이 직접 올리는 "API 공지" 글만 있고, 측정한 가용률이나 응답시간 이력은 없습니다.
- **개발자들이 같은 문제를 반복해서 겪습니다.** "수집 잡이 몇 시간째 멈췄는데 우리 쪽 문제인지 기관 쪽 문제인지 모르겠다"는 이슈가 여러 저장소에 남아 있습니다. 2025년 9월 국가정보자원관리원 화재 때는 공공데이터포털이 약 4주 멈췄습니다([세계일보](https://www.segye.com/newsView/20251023512913)).
- **해외 서버에서는 닿지 않는 API가 있습니다.** 2026-10-10 공개 측정 서비스 [check-host.net](https://check-host.net)의 해외 노드(미국·유럽·일본·싱가포르)에서 재 보니 `apis.data.go.kr`, 법제처, KOSIS 등은 TCP 연결부터 시간 초과였습니다. NEIS·DART·ECOS·KIPRIS는 정상이었습니다. 다만 GitHub Actions(Azure)에서는 이 중 상당수가 닿았습니다(아래 '운영해 보고 알게 된 것'). 해외 리전에 배포하는 개발자에게는 **어느 클라우드에서 닿는지**가 바로 필요한 정보입니다.

## 무엇을 재나

| 단계 | 의미 | 키 |
|---|---|---|
| **L2** | 키 없이 불러 게이트웨이(입구)가 정해진 오류로 답하는지. 예: data.go.kr이면 `SERVICE_KEY_IS_NULL` | 필요 없음 |
| **L4** | 기관이 공개한 샘플 호출(`sample` 키 등)로 실제 데이터가 오는지, 응답 필드 구조가 바뀌었는지 | 필요 없음 |

- 공공데이터포털 게이트웨이를 거치는 6개 서비스는 키 없이 재면 같은 신호를 내므로 화면에서 한 행으로 묶고, 서비스별로 다른 것(폐기·형식 변경)만 따로 적습니다.
- 판정: 응답함 / 일시 실패(한 번) / 응답 없음(두 번 연속) / 형식 변경 / 접근 거부(401·403·429) / 폐기됨(`NO_OPENAPI_SERVICE_ERROR`)
- **해외 측정 위치의 7일 이력 전체에서 한 번도 서버에 연결되지 않은 API(연결 실패·시간 초과만 셈)는 '이 위치에서 닿은 적 없음'으로 따로 표시합니다.** 기관 장애로 오해되지 않게 하려는 것입니다. 처음에는 다른 측정 서비스(check-host.net)에서 막혔던 13곳을 고정 목록으로 썼지만, GitHub Actions에서는 그중 대부분이 닿아 맞지 않았습니다. 그래서 그 위치의 이력으로만 판단합니다. 한 번이라도 닿았던 곳의 실패, 그리고 형식 변경·접근 거부·5xx처럼 서버가 답한 경우는 그대로 판정대로 보입니다.
- 마지막 측정이 평소 측정 간격의 3배(최소 90분)보다 오래된 위치는 '측정 중단'으로 표시합니다. 멈춘 측정이 현재 상태처럼 보이지 않게 하려는 것입니다.
- **L2의 "응답함"은 기관 서버가 실제 데이터를 준다는 뜻이 아닙니다.** 게이트웨이까지 살아 있다는 뜻입니다. 화면에 단계를 함께 표시하는 이유입니다.
- 매 회차 한국 공공기관과 무관한 주소(`https://www.gstatic.com/generate_204`)로 측정하는 쪽 회선을 먼저 확인합니다. 이것이 실패한 회차만 '측정 무효'로 뺍니다. 한국 공공기관을 대조군으로 쓰면 전국 단위 장애가 '측정 무효'로 지워지기 때문입니다.
- 대상과 판정 서명은 [`targets.json`](targets.json)에 있습니다. 판정 로직은 [`lib.mjs`](lib.mjs), 테스트는 [`lib.test.mjs`](lib.test.mjs)입니다.

### 측정 위치

| 위치 | 실행 | 상태 |
|---|---|---|
| GitHub Actions (해외 클라우드, `--scope overseas`) | [`.github/workflows/probe.yml`](.github/workflows/probe.yml), 매시 7분·37분 예약 | 운영 |
| 국내 클라우드 (`--scope domestic`) | [`scripts/probe-and-push.sh`](scripts/probe-and-push.sh)를 국내 VM cron으로 | 준비 중 |

### 운영해 보고 알게 된 것 (2026-10-14~18, GitHub Actions 24회)

- **GitHub 예약 실행은 크게 밀립니다.** 30분 간격으로 예약했지만 3.5일 동안 24회 돌았고, 간격 중앙값은 약 3.5시간이었습니다. 그래서 '측정 중단' 기준을 고정값 대신 실제 간격에 맞췄습니다.
- **check-host.net 해외 노드에서 막혔던 곳이 GitHub Actions(Azure)에서는 대부분 닿았습니다.** 공공데이터포털 게이트웨이 6곳과 KOSIS는 24회 중 22회, 도로명주소는 20회 응답했습니다. 24회 모두 실패한 곳은 ITS(시간 초과)와 브이월드(HTTP 502)이고, 법제처는 24회 중 9회 실패했습니다. 해외 차단 여부는 측정 위치(클라우드)마다 다릅니다.

- **GitHub 러너는 회차마다 IP가 달라, 일부 회차는 한국 서버들이 한꺼번에 막힙니다.** 2026-10-18~25 42회 중 5회는 해외 접속에 민감한 한국 서버 10~12곳이 동시에 시간 초과였고, 같은 시각 한국 회선에서는 20곳 모두 정상이었습니다. 그래서 해외 측정에서 연결 실패가 6곳 이상 겹친 회차는 장애로 단정하지 않고 '측정 무효'로 뺍니다. 실제 측정 간격 중앙값은 약 4시간이었습니다(65회, 실패 0회).

### 뺀 것

- **경기데이터드림**: 측정 도구임을 밝힌 User-Agent에는 응답하지 않고 curl·브라우저 User-Agent에만 응답했습니다(2026-10-11). User-Agent를 위장하지 않으려고 뺐습니다.
- **인증키가 필요한 단계(실제 데이터·신선도)**: 키 관리 설계를 끝낸 뒤 넣습니다.

## 보안

- 위협 모델: 공개 저장소·로그·페이지를 통해 기관 발급 키가 새는 것, 측정이 기관 서버에 부담을 주는 것.
- **인증키를 쓰지 않습니다.** 비밀값(Secrets)도 없습니다.
- 응답 본문은 저장하지 않습니다. 판정 결과, 응답시간, 응답 필드 이름·타입의 해시(지문)만 커밋합니다.
- 오류 메시지는 오류 코드만 남깁니다(라이브러리 예외 메시지에는 요청 URL이 들어갈 수 있기 때문).
- 리다이렉트를 따라가지 않습니다. 워크플로 트리거는 `schedule`·`workflow_dispatch`뿐이고, `pull_request_target`은 쓰지 않습니다. 서드파티 액션은 커밋 SHA로 고정했습니다.
- 국내 VM을 붙일 때는 이 저장소 전용 deploy key만 두고, 데이터 전용 브랜치로 push를 제한할 예정입니다.
- 호출량: API당 많아야 30분에 1회(하루 48회 이하). 공공데이터포털 이용약관 제14조 5항("제공시스템의 성능 저하")을 고려해 정했습니다.
